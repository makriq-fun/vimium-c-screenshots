# Vimium C Screenshots

Форк [Vimium C](https://github.com/gdh1995/vimium-c) с полноценными скриншотами, управляемыми
только с клавиатуры. Расширение работает в Firefox и [Zen Browser](https://zen-browser.app/),
не отправляет изображения в сеть и копирует PNG сразу в буфер обмена.

Кодовая база, история и лицензия Apache 2.0 взяты из оригинального Vimium C. Все штатные
возможности Vimium C сохранены; добавлены только команды скриншотов.

- Исходники: <https://github.com/makriq-fun/vimium-c-screenshots>
- Оригинал: <https://github.com/gdh1995/vimium-c>

## Новые команды

| Клавиши | Команда | Действие |
| --- | --- | --- |
| `s` `s` | `screenShotElement` | Показать буквенные метки, выбрать элемент, затем `s` — скопировать PNG элемента |
| `s` `a` | `screenShotFullPage` | Сразу скопировать PNG всей страницы |
| `s` `v` | `screenShotViewport` | Сразу скопировать PNG видимой области |

В режиме выбора элемента:

1. `ss` — на странице появляются метки для ссылок, кнопок, изображений, таблиц, текстовых
   блоков и карточек (элементов с фоном/рамкой/тенью).
2. Введите метку. Во время ввода показываются только подходящие метки, остальные скрываются.
3. Элемент подсвечивается: затемнение вокруг и синяя рамка, как у инструмента скриншотов
   Zen/Firefox. Предпросмотра в отдельном окне нет.
4. `s` — захватить элемент целиком, скопировать PNG и выйти в обычный режим Vimium C.
5. `Esc` — отмена на любом этапе: и во время меток, и после выбора. Интерфейс и обработчики
   клавиш удаляются.

`sa` и `sv` срабатывают сразу: без меток, подсветки, предпросмотра и подтверждений. После
успешного копирования расширение остаётся в обычном режиме. При ошибке в HUD выводится причина
(слишком большой элемент, запрет захвата, сбой буфера обмена и т. п.).

### Переназначение

Команды — обычные команды Vimium C, их можно переназначить, например:

```
map Xs screenShotElement
map Xa screenShotFullPage
map Xv screenShotViewport
```

Рекомендуемый набор клавиш из `settings-template.json` тоже содержит `ss`, `sa`, `sv`. Если вы
одновременно назначаете `s` на команду (`map s scrollPageDown`) и используете `ss`/`sa`/`sv`,
одиночная команда `s` выполняется после короткой паузы 400 мс; последовательность из двух клавиш
имеет приоритет. В стандартной конфигурации Vimium C клавиша `s` не назначена, поэтому задержки
нет.

## Что попадает в снимок

- **Элемент (`ss`)** — весь элемент по его border-box, включая части за пределами экрана.
  Страница прокручивается по вертикали и горизонтали, кадры сшиваются без обрезки содержимого.
- **Вся страница (`sa`)** — весь документ (`scrollWidth` × `scrollHeight`), включая широкие
  таблицы и длинные статьи.
- **Видимая область (`sv`)** — ровно текущий viewport, без прокрутки.

Во время многотилевого захвата расширение временно скрывает полосы прокрутки, останавливает
CSS-анимации/переходы и убирает каретку. Фиксированные и sticky-элементы скрываются после первого
кадра (для элемента — с первого кадра), поэтому шапка не повторяется на каждом фрагменте.
Собственные метки, подсветка и HUD Vimium C удаляются/скрываются до вызова захвата, поэтому не
попадают в PNG.

Масштаб страницы и `devicePixelRatio` учитываются по фактическому размеру полученного кадра,
поэтому снимок не «съезжает» при зуме и на HiDPI.

## Ограничения

- Команды работают в верхнем документе. Внутри iframe выводится сообщение об ошибке: клавиатурный
  фокус остаётся в iframe, и обработчик меток верхнего документа не получил бы нажатия.
- Элемент, обрезанный прокручиваемым/`overflow: hidden` контейнером, не захватывается частично:
  выводится ошибка. Прокрутка самой страницы (вертикальная и горизонтальная) поддерживается.
- Пределы одного PNG: 32767 px по каждой стороне, 64 мегапикселя, не более 400 кадров. При
  превышении выводится ошибка — неполный файл не копируется.
- Лениво загружаемые изображения могут не успеть появиться. CSS-анимации останавливаются на
  текущем кадре.
- Захват длинной страницы занимает время: один кадр на экран плюс задержка на отрисовку
  (в Chromium дополнительно ~0.6 с между кадрами из-за лимита `captureVisibleTab`).
- Firefox и Zen — основная цель. Chromium MV3 также поддерживается, но сервис-воркер Chrome
  может быть остановлен браузером при очень долгом захвате.
- Постоянная установка в обычном Firefox требует подписи Mozilla. См. раздел о подписи.

## Установка

### Zen Browser (временно, для проверки)

1. Соберите пакет (см. ниже) или скачайте `vimium_c-*-firefox.zip` из CI/Releases и распакуйте.
2. Откройте `about:debugging#/runtime/this-firefox`.
3. «Load Temporary Add-on…» → выберите `manifest.json` в распакованной папке.
4. Откройте обычную страницу и нажмите `s`, `s`.

Временное дополнение живёт до перезапуска браузера.

### Zen Browser / Firefox (постоянно)

1. Подпишите сборку в Mozilla Add-ons (unlisted) — см. раздел «Подпись».
2. Откройте `about:addons` → шестерёнка → «Install Add-on From File…» → выберите подписанный
   `.xpi`.
3. Либо загрузите unlisted XPI на AMO и установите по полученной ссылке.

В Firefox Nightly/Developer Edition можно отключить обязательную подпись в `about:config`
(`xpinstall.signatures.required = false`), но это не рекомендуется для повседневного браузера;
в обычном Firefox такой обход не работает. Расширение сознательно не пытается обходить подпись.

### Linux / Wayland

Отдельной настройки не требуется: используются `tabs.captureVisibleTab` и
`browser.clipboard.setImageData` (Firefox) / `navigator.clipboard` (Chromium). На Wayland
применяются те же WebExtension API; отдельных X11-вызовов в коде нет.

## Сборка

Требования: Node.js 20+, npm, `zip` (для упаковки).

```bash
npm ci

# Firefox / Zen: MV2-пакет
npm run mv2-ff          # результат: dist/ и zip в корне репозитория

# Chromium: MV3-пакет (используется в E2E)
npm run chrome          # результат: dist/ и zip
```

`dist/` — распакованное расширение, готовое для `about:debugging`. Версия берётся из
`manifest.json` (`2.13.3.1`), Firefox ID — из `typings/build/index.d.ts`
(`vimium-c-screenshots@makriq.fun`).

### Тесты

```bash
npm run test:geometry   # чистые функции планирования кадров, Node.js

# Браузерный E2E (Chromium, реальные нажатия и реальный буфер обмена)
npm run chrome
npm install --no-save playwright@1.65.1
npx playwright install --with-deps chromium
xvfb-run -a node tests/e2e/run.js
```

E2E проверяет: `ss` → метка → `s`, `sa`, `sv`, отмену по `Esc` на обоих этапах, отсутствие
повторяющейся фиксированной шапки, захват элемента за пределами экрана, размеры и цвета PNG,
отсутствие интерфейса в кадре, работу при `deviceScaleFactor=2` и зуме страницы, а также
сохранность обычных клавиш Vimium C (`j`, `gg`).

GitHub Actions выполняет эти проверки автоматически (`.github/workflows/ci.yml`).

## Подпись для Firefox

Mozilla подписывает дополнения через AMO. Нужны API-ключи автора дополнения; в репозитории они
не хранятся.

1. Получите ключи на <https://addons.mozilla.org/developers/addon/api/key/>.
2. В GitHub: Settings → Secrets and variables → Actions → добавьте `WEB_EXT_API_KEY` и
   `WEB_EXT_API_SECRET`.
3. Запустите вручную workflow **Sign Firefox package (AMO, manual)**. Он соберёт MV2-пакет и
   вызовет `web-ext sign --channel unlisted`, затем выложит подписанный `.xpi` артефактом.
4. Локальный вариант:

```bash
export WEB_EXT_API_KEY=...
export WEB_EXT_API_SECRET=...
npm run mv2-ff
npx web-ext sign --source-dir dist --channel unlisted \
  --api-key "$WEB_EXT_API_KEY" --api-secret "$WEB_EXT_API_SECRET" --artifacts-dir signed
```

Перед каждой отправкой увеличивайте `version` в `manifest.json`: AMO не принимает повторную
версию. Для listed-канала дополнительно требуется прохождение ревью Mozilla.

## Архитектура

- `content/screenshot.ts` — режим выбора, метки, подсветка, измерение страницы, прокрутка,
  скрытие фиксированных элементов, сообщения с background.
- `background/screenshot.ts` — пошаговый захват через `tabs.captureVisibleTab`, сшивка на
  canvas/OffscreenCanvas, проверка лимитов и копирование PNG в буфер обмена.
- `background/screenshot_geometry.ts` — чистый планировщик кадров (покрыт тестами).
- `content/key_handler.ts`, `background/key_mappings.ts` — поддержка ключа, который одновременно
  является командой и префиксом (для пользовательских раскладок с `s`).
- Команда зарегистрирована как `kFgCmd.screenshot`; имена команд доступны в `map`/`run`, справке
  и настройках.

Разрешения не расширялись: уже имеющихся `<all_urls>`, `clipboardWrite` и `clipboardRead`
достаточно для `captureVisibleTab` и записи PNG. Сетевых запросов, телеметрии и внешней обработки
изображений нет.

## Синхронизация с оригиналом

```bash
git remote add upstream https://github.com/gdh1995/vimium-c.git
git fetch upstream
git merge upstream/master
```

Конфликты ожидаемы в списках команд (`typings/messages.d.ts`,
`background/key_mappings.ts`, `content/commands.ts`), в `manifest.json`/`manifest.v2.json` и в
workflow-файлах. Файлы `content/screenshot.ts`, `background/screenshot.ts`,
`background/screenshot_geometry.ts` и `tests/` добавлены этим форком; при слиянии их не нужно
перезаписывать.
